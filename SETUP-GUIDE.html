Kata Scoring — Setup Guide

How to get the judging system running on a laptop. No programming knowledge needed — just follow each step in order.

Before you start

Gather these first. The whole setup takes about 45 minutes.

  • A laptop — Windows or Mac
  • An internet connection
  • A Google account (a normal Gmail account is fine)
  • The project folder that came with this guide
Do the steps in order. Each part depends on the one before it. If something doesn't look right, stop and check the Problems section at the end rather than continuing.

Part 1 — Install Node.js 10 minutes

This is the program that runs the app on your laptop.

1

Go to nodejs.org in your browser.

2

Click the big green download button that says LTS. Ignore the other one.

3

Open the downloaded file and click Next through the installer. Accept every default — don't change any options.

4

Now open the black text window where you type commands:

  • Windows: press the Windows key, type cmd, press Enter
  • Mac: press Cmd+Space, type terminal, press Enter
5

Type this exactly and press Enter:

node --version
Check: you should see something like v22.11.0. If it says "not recognised" or "command not found", close that window completely, open a new one, and try again. The installer only works in newly opened windows.

Part 2 — Create the Firebase project 10 minutes

Firebase is Google's free service that stores the scores and sends them between phones.

1

Go to console.firebase.google.com and sign in with your Google account.

2

Click Create a project. Name it kata-scoring.

Turn off Google Analytics when it offers it — you don't need it. Click Create and wait for it to finish.

3

In the left menu, click Build → Firestore Database, then Create database.

Choose the location closest to you. Choose Start in production mode.

4

In the left menu, click Build → Authentication, then Get started.

Choose Email/Password from the list, switch the first toggle on, and Save.

Stay on the free plan. If Firebase ever asks you to upgrade or add a credit card, say no. Everything this app needs is free.

Part 3 — Create the five accounts 10 minutes

One login for each judge, plus one for the referee.

1

Still in Authentication, click the Users tab, then Add user.

2

Create these five, one at a time. Use the same password for all five so it's easy to remember — for example kata2026.

referee@kata.local
judge1@kata.local
judge2@kata.local
judge3@kata.local
judge4@kata.local

These are not real email addresses and don't need to be. Nothing is sent to them.

3

You'll now see five rows, each with a long code in the User UID column — something like k3Jd8sLm2NqP...

Copy each one into a notepad file and write next to it which account it belongs to. You need all five in the next part.

Part 4 — Tell the app who is who 10 minutes

This is the fiddliest part. Take it slowly.

The app needs to know which login is the referee and which judge sits in which seat. You do this by adding five small records to the database.

1

Go to Build → Firestore Database. Click Start collection.

Type roles as the Collection ID and click Next.

2

For Document ID, paste the referee's User UID from your notepad.

Then add one field:

Field nameTypeValue
rolestringreferee

Click Save.

3

Now click Add document and repeat for judge 1. Paste judge 1's UID as the Document ID, and add two fields:

Field nameTypeValue
rolestringjudge
seatnumber1
4

Repeat for judges 2, 3 and 4 — same thing, with seat 2, 3 and 4.

Two mistakes people make here. First: the seat must be type number, not string — there's a dropdown next to the field where you pick the type. Second: the Document ID must be the long UID code, not the email address. If judges can't score later, this is almost always why.
Check: your roles collection should now show five documents, each with a long code as its name.

Part 5 — Get your connection keys 5 minutes

1

Click the gear icon at the top left, then Project settings.

2

Scroll down to Your apps. Click the </> (web) icon.

Give it any nickname, leave the hosting checkbox unticked, and click Register app.

3

You'll see a block of code containing lines like apiKey:, authDomain: and so on. Leave this page open — you'll copy from it in the next part.

Part 6 — Set up the project folder 5 minutes

1

Put the project folder on your Desktop and make sure it's named kata-app.

2

Inside that folder, find the file called .env.example. Make a copy of it and rename the copy to just .env — no .example on the end.

On a Mac you won't see this file at first — Finder hides anything starting with a dot. Press Cmd + Shift + . (period) to show them, and again afterwards to hide them.

Windows may also hide the ending. If you see only env after renaming, turn on File name extensions in Explorer's View menu and check the name is exactly .env.

3

Open .env in Notepad (Windows) or TextEdit (Mac). Fill in each value from the Firebase page you left open. Match them up like this:

In the .env fileFrom Firebase
VITE_FB_API_KEYapiKey
VITE_FB_AUTH_DOMAINauthDomain
VITE_FB_PROJECT_IDprojectId
VITE_FB_STORAGE_BUCKETstorageBucket
VITE_FB_SENDER_IDmessagingSenderId
VITE_FB_APP_IDappId

Copy only what's between the quote marks. No spaces around the = sign. Save the file.

Part 7 — Start the app 5 minutes

1

Open the command window again (Part 1, step 4). Type this and press Enter:

cd Desktop/kata-app
2

Type this and press Enter. It downloads what the app needs and takes a couple of minutes. Lots of text will scroll past — that's normal.

npm install
3

Then type this and press Enter:

npm run dev
Check: you should see a web address like http://localhost:5173. Open it in your browser and you should see a sign-in screen. Sign in as referee@kata.local.
Leave the command window open. Closing it stops the app. To stop it deliberately, click in the window and press Ctrl+C.

Part 8 — Load the security settings 5 minutes

This step stops judges from seeing each other's scores. Don't skip it.

1

In the project folder, open the file firestore.rules in Notepad. Select everything and copy it.

2

In Firebase, go to Build → Firestore Database → Rules tab.

Delete everything in the box, paste what you copied, and click Publish.

Check: sign in as judge 1 on the laptop and judge 2 on a phone. Have both submit scores. Neither should be able to see the other's numbers until the referee reveals.

Part 9 — Putting it online (optional)

Only needed if the judges' phones aren't on the same WiFi as the laptop.

In the command window, in the project folder, run these one at a time:

npm install -g firebase-tools
firebase login
firebase init hosting
npm run build
firebase deploy

When firebase init hosting asks questions: choose your existing project, type dist for the public directory, answer Yes to single-page app, and No to GitHub deploys.

At the end it prints a web address ending in .web.app. That's your live link — share it with the judges.

Part 10 — Using it on the day

Setting up the phones

  1. Open the web address in Chrome on each judge's Android phone
  2. Tap the three dots menu → Add to Home screen
  3. Open it from the new icon and sign in with that judge's email
  4. On each phone: set screen timeout to 10 minutes and turn on Do Not Disturb

Running a match

  1. The referee types both competitors' names and taps Create match
  2. Referee taps Open round — the judges' buttons unlock
  3. Each judge sets a score for the red competitor and the blue one, then taps Submit scores
  4. The referee sees which seats have scored, but not the numbers
  5. Once all four are in, the referee taps Reveal result
  6. Referee creates the next match and repeats

The scoreboard screen

Add /?portal to the end of your web address and open that on a TV or projector. It needs no login and updates by itself.

Problems

What you seeWhat to do
"node is not recognised" Close the command window completely and open a fresh one. If it still fails, reinstall Node.js.
"No role assigned to this account" The Document ID in the roles collection doesn't match that user's UID. The screen shows you the correct UID — copy it and check Part 4.
Judge taps Submit and nothing happens Either the rules weren't published (Part 8), or the seat field was saved as text instead of a number (Part 4).
Sign-in page is blank or errors The .env file is wrong. Check for stray quote marks or spaces, then stop the app (Ctrl+C) and run npm run dev again — it only reads that file on startup.
Phones can't open the address They must be on the same WiFi as the laptop, or you need to do Part 9.
"Missing or insufficient permissions" The rules in Part 8 weren't published. Redo that step.

Changing the score range

The app scores from 5.0 to 10.0 in steps of 0.2. To change that, a developer needs to edit two files — src/firebase.js and firestore.rules — and republish the rules. Changing only one will make submissions fail.

Good to know

  • Nothing is deleted automatically — past matches stay in the database
  • Free limits are 50,000 reads and 20,000 writes per day. One match uses about 12 writes, so you won't come close.
  • If a judge's phone dies, sign in as that judge on a spare phone. Everything carries on.
